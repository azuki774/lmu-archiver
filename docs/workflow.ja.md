# ワークフロー

[English](workflow.md)

## 取得と保存

`lmu-archiver sync` は次の処理を1回の実行で行う。

1. 起動中のLMUからSteamセッションチケットを取得し、RaceOSで認証する。
2. 認証プロフィールから現在のDR/SRとSteam IDを取り出す。
3. 共通のHTTPクライアントで結果APIをページングして取得する。
4. 結果JSON、資格情報を除いたプロフィール、元の観測日時と識別子を含む
   マニフェストを、取得単位のディレクトリへ保存する。
5. 自分のレース結果とDR/SR観測を、同じSQLiteトランザクションで保存する。

チケットやアクセストークンは保存しない。既定のイベント種類は `daily,specialevent`。
取得は空配列またはnullで終了し、繰り返しページやHTTPエラーは失敗として扱う。
取得失敗時はDBを更新せず、部分取得ファイルの保存先をエラーに表示する。
DB保存に失敗しても取得済みファイルは残る。自動リトライは行わない。

## オフライン再取り込み

```sh
lmu-archiver sync --skip-download --input /path/to/capture
lmu-archiver sync --skip-download --input /path/to/results.json --steam-id YOUR_STEAM_ID
```

ネットワークアクセスも認証もしない。完全な取得ディレクトリからは結果とDR/SRを
再取り込みし、同じ取得識別子の観測は重複させず、元の観測日時を保持する。
従来の結果JSONだけの場合は結果のみ取り込み、DR/SRを推定しない。
マニフェストと取得ファイルは変更せず一緒に保管する。

## 参照とHTTP API

`races` / `ratings` は保存済みDBを読み、人向けの表または `--json` を出力する。
`serve` は同じ検索処理を読み取り専用のHTTP APIとして提供する。
参照時に外部API取得・DB作成・マイグレーションは行わない。
単一プレイヤーのDBではSteam IDを自動選択し、複数の場合は設定または引数で指定する。
サーバーには認証やTLSがないため、既定のループバックで使用し、外部へ公開しない。

参考レートはイベント日時以前の最新観測値を検索時に選ぶもので、レース直後の
確定値ではない。生の結果JSONは別ファイルとし、DBには自分の情報を正規化して保存する。

設定とコマンドの詳細は [README](../README.md)、DBは [SQLite reference](sqlite.md) を参照。
